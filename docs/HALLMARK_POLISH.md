# Hallmark 앱 화면 보완

사용자가 Hallmark 적용을 명시해 홈 스코어보드와 AI 페이지에 추가 적용했다. 이전 Impeccable 수정은 별도 커밋 `5236700`로 보존했다. 대상은 기존 앱의 polish이며, `DESIGN.md`에 고정한 차콜·글래스·라임과 8px 간격을 따른다.

## 적용 범위

- 기존 검색창 노출, SVG 조작 아이콘, 모바일 12px 메뉴 글자, 압축한 AI 조작부를 유지했다.
- `tokens.css`에서 색·폰트·간격을 관리하고 홈, AI, 순위표, 경기판이 같은 토큰을 사용하게 했다. 기존 그림자·배경 조명은 사용자 참조에 맞춰 보존했다.
- 날짜·검색 입력칸에 대비가 확보된 테두리를 적용했다. 검색 필드 자체의 높이를 인접 버튼과 같은 48px로 맞췄다.
- 비활성 버튼에 네이티브 disabled 속성과 함께 색·배경·커서를 구분했다. 키보드 포커스는 즉시 나타난다.
- 홈과 AI의 제목 크기, 좌우 정렬과 색상 기준을 통일했다. 원래 36px/28px 제목 체계를 유지했다.
- 출처·조회 시각·지연 상태를 별도 항목으로 표시하고, 실제 의미를 가진 SVG로 링크 화살표와 관심 경기 아이콘을 통일했다.
- JavaScript를 끈 홈 화면에는 조회 조건을 설명한다. 팀, 점수, 시즌 기록, 원래 수집 시각과 API 연결 로직은 임의 생성하거나 재설정하지 않았다.
- 신규 토큰 파일을 서버 공개 목록, Pages 게시 목록 및 서비스워커에 함께 등록했다. `.hallmark` 자료는 개발 경로로 분류했다.

새 사진이나 가상 통계, 고객 인용, 장식 차트는 사용하지 않았다. 기존 로고 URL의 실제 접근 여부 및 사용 권한은 별도 데이터 검증 대상이다.

## 원본과 실행

[Nutlope/Hallmark](https://github.com/nutlope/hallmark)의 커밋 [`04977e15f3dfd6ee4b74c887dac3eb52665d6c92`](https://github.com/nutlope/hallmark/tree/04977e15f3dfd6ee4b74c887dac3eb52665d6c92), 버전 2.0.0, MIT를 검토해 사용했다. 클라우드에 제공된 Hallmark 스킬을 적용했고, 검사 스크립트는 검토한 임시 체크아웃에서 실행했다. 원본과 검사 스크립트 SHA-256은 [provenance.json](../.hallmark/provenance.json)에 기록했다. 전역 훅이나 에이전트 설정은 설치하지 않았다.

대상은 `tokens.css`, `score-center.css`, `ai-dashboard.css`, `watchboard.css`, `football-standings.css`와 로컬 서버의 홈/AI 두 경로다. 시스템 Chromium과 임시 개발 도구 `puppeteer-core`로 원본 `sloplint --scope app --genre modern-minimal --render`를 실행했다. 마케팅 페이지의 히어로·섹션 수·단어 수 기준은 앱 범위에 적용하지 않는다.

| 항목 | 결과 |

| 시각 검토 | 별도 에이전트의 새 컨텍스트 검토: `ship`, 수정 요구 0, 방향 격차 없음 |
| 프로젝트 테스트 | 65개 통과 |
| 브라우저 동작 검사 | 320·360·390·768·1024·1440px에서 통과 |
| 원본 스킬 무결성 | 기존 프로젝트 고정 스킬 3개, 88개 파일 일치 |

브라우저에서는 검색·빈 결과 복구·관심 경기·경기 고정 및 해제·키보드 필터 열기/닫기·긴 팀 이름·상세 복귀·순위표·AI 리그 전환을 확인했다. 문서뿐 아니라 주요 컨테이너의 실제 경계도 검사해 `overflow-x: clip`이 넘친 콘텐츠를 감춘 결과가 되지 않도록 했다. 네이티브 설명 패널은 닫혔을 때 내부 글자의 `checkVisibility`가 false이고 키보드로 정상 열린다.

Hallmark가 생성한 이미지에는 375px 전체 페이지와 1280×800, 1440×900, 1920×1080 화면 및 1440px 전체 페이지가 포함된다. 별도 검토는 앱 polish 규칙에 따라 두 경로의 1440px 전체 페이지 전후 이미지를 사용했다. 기존 AI 화면은 두 팀 사이 거리가 더 짧았지만, 새 화면에서도 정보나 동작의 접근성이 낮아졌다는 결함은 발견되지 않았다.

## 예외와 한계

- **39b:** 경기 카드는 팀명·점수·상태를 함께 여는 큰 버튼이다. 일반 입력 버튼의 높이 기준으로 축소하면 기존 스코어 탐색을 해치므로 큰 누름 영역을 유지했다.
- **72:** 닫힌 네이티브 details 내부 단락의 기하 정보를 검사기가 넘침으로 읽었다. 실제 표시 여부와 키보드 열기/닫기를 검증해 예외로 기록했다.
- 사용자 참조에서 지정한 글래스·고정 배경 조명은 DESIGN.md를 근거로 유지했다. 공통 컴포넌트 반복과 4가지 글자 굵기는 앱에서 서로 다른 역할을 구분한다.
- 최종 Hallmark 경고 2개는 실제 조회 시각 변경과 검사 환경의 cdnjs Font Awesome 로드 실패다. 기록을 수정해 동일한 시각으로 꾸미지 않았다. 현재 스코어/AI 조작부는 SVG와 시스템 폰트를 사용하며, 외부 CDN을 쓰는 레거시 화면 전체의 검증을 주장하지 않는다.
- Impeccable 수동 검출도 마무리에 한 번 실행했다. 더 넓은 HTML/레거시 영역에서 경고 88개가 남았다. 이 결과와 Hallmark의 특정 앱 화면 검사 범위를 혼동하지 않으며, 전체 사이트 접근성 인증이나 보안 감사 통과로 표현하지 않는다.
- 데이터 감사는 구조가 유효하지만 팀 ID 미확정 29행과 오래된 출처 경고를 유지한다. 공급 장애, AI 자료 갱신 및 Firebase 연결 완료는 이 디자인 검사의 결과가 아니다.

전후 비교는 작업 환경의 `.hallmark/compare.html` 및 `/workspace/artifacts/hallmark/compare.html`, 원본 검사 결과는 `/workspace/artifacts/hallmark/`에 보존한다. 이미지는 Git이나 운영 사이트에 게시하지 않는다.
